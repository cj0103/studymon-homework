# 宝可梦作业激励游戏 · 关都篇

一个**家庭自用**的作业激励应用：孩子每天完成作业、家长审核通过后，队伍里的宝可梦获得经验、升级、学招式；周末可以挑战道馆、在野外捕捉宝可梦。用游戏化的正反馈，把"坚持打卡"这件事变成孩子自己的期待。

> **版权免责声明**：本项目为家庭自用、非盈利的同人软件，仅为个人学习用途。代码与玩法规则为自制，**本仓库不包含任何任天堂 / Game Freak / The Pokémon Company 的图片、音频或图鉴数据**（立绘、战斗精灵、叫声、官方图鉴数据表等均需使用者自行获取，见"素材准备"）。宝可梦及相关角色形象均为其权利人商标与著作权作品。如权利人认为有侵权之处，联系我们即删。

## 它解决什么问题

低年级孩子写作业需要即时反馈，但"贴纸小红花"太廉价，"买玩具"太昂贵且无持续性。我们的思路是把反馈做成一条可持续的成长曲线：**作业 → 打卡 → 经验 → 升级 / 学新招 / 进化 → 周末对战和捕捉更有底气**。经验**只能**来自作业打卡，游戏里没有别的获取途径，所以孩子想练级就只能坚持——这正是设计的目的。

家长侧保留完整控制权：所有打卡必须家长审核通过才结算经验，家长可以扣减批准（少发）或整条驳回（清零），防止乱勾一气。

## 核心规则（家庭自定，已冻结）

| 规则 | 数值 | 设计意图 |
|---|---|---|
| 每日定额经验 `daily_base_exp` | 230 | 与勾选几项无关，只看"今天有没有做"，避免孩子为凑数乱勾 |
| 快手奖励 | 学习日 21:30 前提交并获批 ×1.2 | 鼓励早做完，不拖到睡前 |
| 双休日 | 不参与快手奖励 | 周末节奏放松，不制造焦虑 |
| 每日上限 `daily_cap` | 320 | 超出部分顺延到次日发放，杜绝"一天刷满" |
| 连击大奖 | 连续获批满 7 天额外 +50 | 奖励的是"坚持"本身 |
| 扣减批准 / 驳回 | -10 / -20；驳回=当天全扣 | 家长有梯度化的调节手段 |
| 经验分配 | 队伍平分 或 主力 60% + 后备各 20% | 后备也保底吃经验，敢上新生 |
| 等级上限 | Lv50 | 关都篇毕业线 |
| 野生等级 | 按区域静态等级带，封顶=本区道馆推荐级 −4 | 保证"跳一跳够得着"，不会偶遇即碾压 |
| 每日捕获额度 | 周末各 3 次（学习日由家长开关放行），遭遇即扣 | 捕捉是"奖励时段"，不是无限刷 |
| 未收录加权 | 图鉴没记到的野怪遭遇权重 ×5（选区猎捕可选区） | 鼓励补图鉴，保留重复遭遇野趣 |
| 重复捕捉 | 再遇到已有怪 = 经验包（喂给同谱系伙伴约 +1 级） | 重复不白抓，也不复制粘贴同链双怪 |
| 道馆赠礼 | 每过一馆送一只传说伙伴，**封印 7 天**后激活 | 见下 |

**封印伙伴（最用心的一条设计）**：打赢道馆赠送的卡比兽、急冻鸟等传说宝可梦并不直接可用，而是入库为"封印"状态，**从获得那天起独立计时**，逐日打卡获批连续满 7 天才激活，激活等级等于该道馆的推荐等级（如 1 馆卡比兽 → Lv16）。中途漏卡或驳回，只有这一只重新起算，不影响全局连击。这样既给了孩子一个具体的长期目标，又不会出现"刚拿到就满级参战"的廉价感。

**捕捉谱系（一条后来补上的重要口径）**：图鉴点亮、野外遭遇加权、重复捕捉结算三处共用同一个"曾经抓到"集合 = 当前背包 ∪ 每只的进化前身（只向前身回溯，不向进化后穿透）。孩子把独角虫练成大针蜂后，图鉴里的独角虫、铁壳蛹保持点亮，野外也不会再把"未抓获"的低级形态按 ×5 概率刷回来、导致队伍里同时出现小拉达和拉达。

**规则口径**：皮卡丘不进化（孩子的情感依恋）、破坏光线 Lv28 才学、招式表按初代精简、经验只来自打卡。

## 对战体验

回合制文字战斗做了完整的"演出层"：对战画面上下对峙（敌上我下，正面/背面像素图分离），招式面板上每一招带**相克预判标识**——红单箭头 ×2、红双箭头 ×4、绿箭头打折、灰色大叉无效（不禁用，让孩子自己试错）；伤害逐条 0.8s/拍播放，掉血条动画、受击闪烁、击倒下沉、伤害飘字，buff/debuff 以徽章常驻。属性克制表前后端同源（专项断言逐格一致），不会出现"前端说有效、后端算无效"的错位。

## 技术栈

- **后端**：Python 3.13 + FastAPI + 自研轻量 DB 层（同一套 SQL 双方言适配）
- **数据库**：SQLite（生产即 SQLite 单文件，备份=拷一个文件）；亦支持 MySQL（环境变量 `PKM_DB_ENGINE` 切换，开发调试用）
- **前端**：**零构建、零框架**——原生 HTML + JS 单页（`index.html` 孩子端 / `parent.html` 家长端），PWA manifest 支持"添加到主屏幕"当 App 用。刻意不引入 React/Vue：家庭项目要能一眼读完全貌、十年后还能跑
- **部署**：腾讯云 ECS + systemd + 原生 HTTP（无 Nginx 反代），paramiko 脚本一键部署（部署纪律：备份含库 → 停服 → 上传 → 编译与新旧实现核验 → 重启 → probe 逐字段比对孩子数据 → 清理）
- **设备令牌**：孩子端用 `?k=<token>` 免登录链接（可生成二维码 + 桌面快捷链接），家长端 JWT

## 快速开始

```bash
cd backend
python -m venv venv && source venv/bin/activate    # Windows: venv\Scripts\activate
pip install fastapi uvicorn pymysql bcrypt pyjwt paramiko  # paramiko 仅部署脚本需要

# 1) 建表 + 种子账号（默认 SQLite，自动建本地文件库）
python app/init_db.py

# 2) 起服务（工作目录必须是 backend/）
PKM_DB_ENGINE=sqlite python -m uvicorn app.main:app --port 8300
# Windows PowerShell: $env:PKM_DB_ENGINE="sqlite"; python -m uvicorn app.main:app --port 8300
```

打开 `http://127.0.0.1:8300/` 即孩子端，`/parent` 为家长端。首次登录后请在家长端「成员管理」里立刻改掉种子账号的默认 PIN，并为学习平板签发设备令牌。

> MySQL 模式：先建库 `CREATE DATABASE pokemon_homework CHARACTER SET utf8mb4`，再用环境变量 `PKM_DB_HOST / PKM_DB_USER / PKM_DB_PASS` 覆盖默认值（默认是本机 root 无密码的开发配置），并执行 `sql/01_business.sql`、`sql/02_device_token.sql`。

## 测试与部署

```bash
python _smoke_all.py     # 推荐：单进程 reset → 起服务 → 全量冒烟 + 各版本专项回归
python smoke_test.py     # 仅端到端冒烟：登录→组队→打卡→审核→经验→升级→驳回→战斗闸门
```

**跑冒烟测试前必须先 `python reset_game.py`**（`_smoke_all.py` 已内置这步）——脚本 1b 节会断言设备令牌恰好是种子状态的 3 条，残留数据会导致假失败。

部署脚本为一次性使用（每个 `_deploy_ecsN.py` 对应一轮上线，内部含服务器地址与凭据，**不入库**）。通用流程是：远端备份（含库文件）→ 上传变更文件 → `py_compile` 语法校验 + 新旧实现 grep 核验 → 数据迁移（仅结构变更时）→ probe 逐字段比对孩子数据 → 清 `__pycache__` 重启 systemd → 公网 HTTP 200 验证 → 二次 probe 确认数据无损。**只要不是表结构变更，一律不跑迁移、绝不 reset 生产库**——孩子的进度是项目里最重要的东西。

## 已知边界与后续

- **无并发与多租户考虑**：单家庭使用，账号体系是「1 家长 + N 孩子」，没做注册流程和找回密码
- **无 HTTPS**：当前 HTTP 直连，令牌在局域网/家庭使用前提下可接受；对外分享前应加 TLS
- **素材无缓存策略**：开发期刻意禁缓存，正式长期跑建议前置 Nginx 做静态缓存
- **数值未经长期验证**：230/320 这套经验曲线是按"开学第一天就要有升级正反馈"倒推的，实践中期可能要调
- **Lv50 封顶的实现是约定式**：等级经验表按生成时只写到 Lv50，封顶靠数据表边界而非运行时 `min(50, …)` 硬断言；若重生成数据表需注意保持这一边界
- **招式数值为初代口径**：与现行正作（Let's Go / SV）存在差异，属有意冻结；招式审计见 `backend/moves_compare.md`
- 待办：玩法说明页（`guide.html`）与规则变更的同步自检（历史上多次出现规则改了、说明页没跟上）
